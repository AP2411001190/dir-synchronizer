Repository / Directory Synchronizer

CSE 302 Operating Systems · Group 7 · Project ID 4 · SRM University-AP

A client-server application that watches a local folder and keeps a remote folder identical to it, in the way Dropbox does. The client detects file changes, hashes the content, and sends only what changed. The multi-threaded server stores the files and keeps an index of them.

How it works

Client                                           Server
┌─────────────┐  event   ┌──────────┐  TCP   ┌───────────────┐
│ Watcher     │ ───────► │  Queue   │ ─────► │ Thread pool   │
│ (producer)  │          │ (blocks) │        │ (8 workers)   │
└─────────────┘          └────┬─────┘        └──────┬────────┘
                              │ consumer            │ mutex
                         ┌────▼─────┐        ┌──────▼────────┐
                         │ Uploader │        │ Index + files │
                         │ SHA-256  │        │ remote_store/ │
                         └──────────┘        └───────────────┘
  1. The watcher thread sees a create, modify, or delete event and puts it on a queue.
  2. The uploader thread takes events from the queue, computes the SHA-256 hash, and skips the upload if the hash matches the last synced one.
  3. The server hands each connection to a worker thread. The worker locks the shared index, writes the file, and updates the hash.
  4. If the connection fails, the client retries with exponential backoff.
